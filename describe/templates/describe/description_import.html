Instructions

Make sure your CSV file follows the following format:

  • One description per row.
  • The CSV file must have a variety_name column, containing the name of the variety.
  • The CSV file must have a description_name column, which is an identificative name of the description.
  • The CSV file must have one column for each characteristic of the chosen protocol; these columns should be named ncharY where Y is the numeric ID of the characteristic within the chosen protocol. These columns should contain the Notes' (or Expressions) IDs constituting the Description. Missing values should be left as empty cells. Only valid Notes (i.e. present in the chosen protocol) will be accepted.
  • The CSV file can't have more than 50 rows*.

If the variety name already exists in the database, the data will be added to that variety. Otherwise, a new variety will be created.

If two varieties with the same name exist in the database, you will be prompted to choose the correct variety.

If a description with the same name exists for the variety, you will be prompted to choose a different name.

After the initial validation, you will be able to review the imported data and correct any errors. Hovering an invalid field with the mouse will display an explantion of the error.

If not changed, invalid Notes will not prevent the import of the record. They simply will be missing from the imported Description. In this way, you can basically use any notation for missing Notes (like 'NA', 0, etc.); however, if you don't want be confused by seeing them as errors you should set the cells containing missing notes as blank.

Once you have reviewed and corrected any errors, click "Submit" to import the data.

*Note: For performance reasons, only 50 records can be imported at a time.
